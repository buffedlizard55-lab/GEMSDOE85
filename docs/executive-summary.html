  1. Sign in to DrivenData. Go to the GEMS Prize submissions page. You must be signed in and joined to the competition; the data and submission pages redirect to a login otherwise.
  2. Click “New submission”. The form has exactly two inputs: File to submit and an optional Note.
  3. Choose the file you downloaded in step 0. The form accepts a single-band GeoTIFF (.tif) or a .zip containing one GeoTIFF. This file is a plain .tif; a zipped twin is also published on the front page if you prefer that route.
  4. Paste the note. The form says: “A short comment to help you or your team tell submissions apart later e.g. clustering with k=25”. Use this, which is already generated for this exact file: 
    H85-1 GEO-Pb 2of3-physics juxtaposition crest, 90000 dots sep4px, 0 within 200m of catalogue, holdout DTI 0.0984 (UNSCORED)
  5. Submit. The scored result appears on your submissions page, and the best public score appears on the leaderboard. Record the receipt — a score is ORGANIZER-CONFIRMED only when it is copied from that page.

If the upload is rejected

errorcausefixed here by
Predicted values must be in range [0, 1] A NaN (or an out-of-range value) anywhere in the raster. NaN ≤ 1 is False under IEEE-754, so a NaN-filled margin can fail a naive range check even though the written format page allows nan outside the bounds. The primary file is all-finite: zeros outside the footprint, no nodata tag. validate() asserts no_nan_inside_footprint, all_finite_whole_raster and values_in_0_1_whole_raster on the written bytes before the file is published.
CRS / shape / transform mismatchRaster not on the competition grid. assert_grid() compares against sample_submission.tif; transform_matches_template and crs_epsg_32611 are in the check table.
Multi-band or wrong dtypeMore than one layer, or not float32. single_band and dtype_float32 checks.
