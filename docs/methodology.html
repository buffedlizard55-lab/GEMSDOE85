Rank 3 — H3: Exact Dual-Expectation (p_hat, q_hat) Bayes-Calibrated Submodular Dinkelbach 300 m Dot Selection

  • Specific Layers / Inputs Used: Out-of-fold calibrated trace crest probability $\hat{p}(x) = \mathbb{P}(x \in G \mid \mathcal{F})$ mapped via exact Bayes prior shift to unseen target density $\pi_{\text{target}}$, paired with OOF-calibrated 300 m max-kernel proximity $\hat{q}(x) = \mathbb{E}[\max_{v \in G} K(x, v) \mid \mathcal{F}] \in [0, 1]$ and B = 2 px (<= 200 m) fold-visible halo pruning.
  • Physical / Mathematical Signature:
  • Maximizes the exact global fractional DTI expectation $\widehat{\mathrm{DTI}}(S) = \widehat{T}(S) / (0.8\,P_{\text{tot}} + 0.2\,\widehat{T}(S) + 0.2\,\widehat{F}(S))$ via Minoux lazy-greedy submodular updates over all 29 kernel offsets $K(\delta) > 0$, halting automatically at the exact unimodal Dinkelbach optimum $t^\star = \arg\max_t \widehat{\mathrm{DTI}}(S_t)$ where $\Delta\widehat{T}(u \mid S) = \frac{0.2\,\tau\,(1 - \hat{q}(u))}{1 - 0.2\,\tau}$.
  • Why It Improves Hidden-Fault Recovery Under DTI:
  • Automatically places dots every ~3.0 px (300 m) along linear fault crests, tightens spacing to 2.0 px on high-certainty fault junctions/stepovers, widens spacing to 3.5–4.0 px on lower-probability tips, suppresses isolated 1 px speckle blobs whose 29-cell integral $\Delta\widehat{T}$ is small even if peak $\hat{p}$ is moderate, and chooses total dot budget without arbitrary magic constants.
  • Named Mimic / Failure Mode & Mitigation: Over-confident uncalibrated tree probabilities inflating $\widehat{q}(u)$ $\to$ mitigated via out-of-fold isotonic calibration against held-out fold segments before Bayes prior scaling.
  • Difference from Prior Implementations: Fixes src/gems85/emitter.py's sum_delta p * k > 1 bug (3x over-estimation of q_hat on 1 px lines) and replaces isotropic d = 2.8 Poisson thinning.
  • Expected DTI Gain vs Compute Cost: High (Rank 3) — ~2.5 s per full-footprint emission pass.

The ordering is inverted, and the cause is mechanical rather than scientific. The three artifacts at the top were built with a hard exclusion of every pixel within 2–3 px of the full catalogue. A hide-and-recover holdout then hides some catalogue segments and asks the artifact to find them — but the artifact has already deleted every dot near them. Its score is forced to ≈ 0 by its own success condition. Hedge-v2, which emits 60,988 dots directly on the catalogue, is rewarded for exactly the behaviour the live scorer punishes.

Consequence, and the fix applied here: a hide-and-recover holdout can only be used to evaluate a rule, re-executed per fold with only that fold's visible catalogue — never a finished raster. src/gems85/holdout.py::score_folds takes a callable and rebuilds per fold for exactly this reason; score_static exists only for the duplicate check and carries this warning. Every sibling repository that reported a Spearman ρ between a static-artifact holdout and the live board was measuring this artifact, not an instrument. Logged as IR-85-001.

The metric, reduced — and what it says about every design choice in this repo

All formulas are transcribed from the official problem description and verified in tests/test_metric.py (11 tests, including an O(N²) brute-force transcription at 1e-9 and the organisers' own worked example).

Source: https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/

1. The published definitions

k(d) = (1 - d/R)_+ ,  R = 300 m  (= 3 pixels at the competition's 100 m resolution)

TP_w = sum_{g in G}        max_{x : d(x,g) <= R}  p(x) k(d(x,g))
FP_w = sum_{x : p(x) > 0}  p(x) [ 1 - max_{g in G} k(d(x,g)) ]
FN_w = sum_{g in G}      [ 1 - max_{x : d(x,g) <= R} p(x) k(d(x,g)) ]

DTI  = TP_w / (TP_w + alpha*FP_w + beta*FN_w + eps) ,   alpha = 0.2, beta = 0.8

Organisers' worked example: TP_w = 3.00, FP_w = 1.89, FN_w = 2.00 → 3.00 / (3.00 + 0.2·1.89 + 0.8·2.00) = 0.6027 → published as 0.60. tests/test_metric.py::test_published_worked_example_combination ✔

Implementation note. Both maxima are grey-scale morphological dilations with the same non-flat structuring element — the 29-pixel disc of radius 3 weighted by k. So the metric is computed exactly, in O(29·N), with no approximation. kernel_offsets() returns exactly 29 offsets and k(0)=1, k(3)=0; both asserted in the tests.

2. Two exact identities

Writing T = TP_w, F = FP_w, K = |G|, S = Σ_x p(x), M = Σ_x p(x)·max_g k(d(x,g)):

identity why test
FN_w = K − T each FN term is 1 − the same max that TP sums test_fn_identity_equals_K_minus_TP
FP_w = S − M regroup the FP sum by prediction pixel test_fp_identity_equals_S_minus_M

Substituting the first gives the design equation:

            T                                       1           alpha·F     beta·K
DTI = -------------------------            <=>   ------- = alpha + ------- + -------
      alpha·(T + F) + beta·K                       DTI              T           T

K is common to every submission in a round, so ranking on the leaderboard is ranking by T / (alpha·F + beta·K) and by nothing else — not by pixel count, not by visual plausibility.

3. Binary predictions are optimal (why this repo ships dots, not a heat map)

Hold every pixel but x fixed. T is affine in p(x) on each linear piece of the max, and F is exactly affine in p(x). A ratio of two affine functions is monotone on an interval, so its maximum over p(x) ∈ [0,1] is at an endpoint: 0 or 1. Graded confidence is therefore weakly dominated, pixel by pixel.

Also verified empirically: test_scaling_monotonicity shows DTI(λp) is strictly increasing in λ, so there is never a reason to scale a prediction down.

4. The marginal rule (the only emission rule used here)

Adding mass at x which captures t of new truth-weight and wastes f = 1 − k(x,G):

new DTI > old DTI   <=>   t > [ alpha·DTI / (1 − alpha·DTI) ] · f
DTI level bar on t per unit wasted mass

Consequence that matters. The bar rises with the score you already have, so the optimal emitted mass is a function of the achieved DTI, and a budget tuned on a low-scoring proxy does not transfer to a high-scoring live board. This repo measures budget behaviour on the holdout but never imports the holdout's optimum directly — see docs/research/budget.md.
